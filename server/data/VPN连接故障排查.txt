# VPN 连接故障排查完整指南

## 一、错误代码 808
**现象**：连接 VPN 时提示“错误 808：无法建立与远程服务器的连接”或“端口 808 被占用”。

**常见原因**：
- 本地 8080 端口被其他程序占用（如代理软件、Web 服务、开发工具）。
- 防火墙（Windows Defender、企业防火墙）拦截了 VPN 出站流量。
- VPN 服务器端 8080 端口未开放或服务宕机。

**解决步骤**：
1. **关闭所有代理软件**：包括 Clash、Shadowsocks、V2Ray、Charles、Fiddler 等，确保它们完全退出。
2. **检查端口占用**：
   - 以管理员身份打开命令提示符（cmd）。
   - 输入 `netstat -ano | findstr 8080`，查看占用该端口的进程 PID。
   - 输入 `taskkill /PID [PID] /F` 强制结束该进程（例如 `taskkill /PID 1234 /F`）。
3. **临时关闭防火墙**：
   - 打开“Windows Defender 防火墙” → “启用或关闭 Windows Defender 防火墙”，勾选“关闭 Windows Defender 防火墙（不推荐）”，测试 VPN 连接。
   - 若成功，则需添加 VPN 程序的入站/出站规则（路径：防火墙高级设置 → 入站规则 → 新建规则 → 程序 → 选择 VPN 客户端路径 → 允许连接）。
4. **更换 VPN 端口**：如果 VPN 客户端支持，可手动更改本地监听端口（如改为 8081），避免冲突。
5. **重启 VPN 服务**：在“服务”管理器中找到 VPN 相关服务（如“Remote Access Connection Manager”），右键重启。
6. 若以上无效，联系网络管理员确认服务器端 8080 端口是否正常。

## 二、错误代码 619
**现象**：提示“错误 619：无法建立到远程计算机的连接”，多发生在 L2TP/IPSec 协议下。

**常见原因**：
- VPN 服务器地址或端口配置错误。
- 运营商网络屏蔽了 IPSec 协议（部分家庭宽带）。
- 本地防火墙或 NAT 设备阻止了 GRE（通用路由封装）或 UDP 500/4500 端口。

**解决步骤**：
1. **检查服务器地址**：确认 VPN 连接属性中的服务器域名/IP 正确无误。
2. **切换协议**：如果客户端支持，尝试从 L2TP 切换为 SSTP 或 OpenVPN（TCP 模式），避免运营商封锁。
3. **修改注册表（Windows）**：
   - 运行 `regedit`，定位到 `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\RasMan\Parameters`。
   - 新建 DWORD（32位）值，命名为 `ProhibitIpSec`，设置为 `1`，重启电脑（此操作可绕过某些 IPSec 限制，但可能降低安全性）。
4. **检查防火墙端口**：确保防火墙允许 UDP 500、4500 以及 GRE 协议（IP 协议号 47）。
5. **尝试使用手机热点**：排除公司网络限制，若热点能连，则需联系公司 IT 调整 VPN 服务器或更改网络策略。

## 三、VPN 频繁掉线或速度慢
**现象**：连接成功但每隔几分钟断开，或传输速度极慢。

**可能原因**：
- 网络不稳定（WiFi 信号弱、丢包率高）。
- VPN 客户端 Keep-Alive 设置过短。
- MTU（最大传输单元）设置不匹配。

**解决方案**：
1. **检查网络稳定性**：用 `ping -t [VPN服务器IP]` 观察延迟和丢包率，若丢包>5%则需改善本地网络。
2. **调整 Keep-Alive**：在 VPN 客户端高级设置中，将“空闲超时”调至 30 分钟或更长。
3. **优化 MTU**：
   - 在命令提示符中执行 `netsh interface ipv4 show subinterfaces` 查看当前 MTU。
   - 尝试降低 MTU 值（如 1400）：`netsh interface ipv4 set subinterface "以太网" mtu=1400 store=persistent`。
4. **更换 DNS**：将 DNS 改为 8.8.8.8 和 114.114.114.114，避免 DNS 解析延迟。
5. 若问题持续，建议联系 IT 支持检查 VPN 服务器负载。

## 四、VPN 连接成功但无法访问内网资源
**现象**：VPN 显示已连接，但无法访问共享文件夹、内部网站或邮件服务器。

**可能原因**：
- 未启用“通过 VPN 发送所有流量”（未配置默认网关）。
- 路由表缺少内网网段的路由。
- DNS 后缀未正确添加。

**解决**：
1. 在 VPN 连接属性中，勾选“在远程网络上使用默认网关”（IPv4 设置 → 高级 → 使用默认网关）。
2. 手动添加路由（如内网网段 10.0.0.0/24）：
   - 先获取网关：`ipconfig` 查看 VPN 接口的网关。
   - 执行 `route add 10.0.0.0 mask 255.255.255.0 [VPN网关IP]`。
3. 设置 DNS 后缀：在 TCP/IP 高级设置中，添加公司域（如 `company.local`），并勾选“附加主 DNS 后缀”。
